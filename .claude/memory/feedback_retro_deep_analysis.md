La retrospectiva NO es solo documentar lo que se hizo. Debe incluir un análisis profundo del panorama completo.

**Why:** Jorge pidió explícitamente que al hacer la retro se reflexione viendo "todo el panorama" y se detecten cosas a sumar a la lista de tareas o mejorar de las implementaciones. Sin este paso, la retro es burocracia vacía.

**How to apply:**
- Antes de documentar, delegar a sub-agentes un audit completo de los archivos modificados
- Buscar: bugs potenciales, edge cases, validaciones faltantes, UX gaps, código duplicado, inconsistencias
- Pensar como usuario final del negocio real
- Cada mejora detectada → item de roadmap con documento
- Priorizar: CRITICO > ALTO > MEDIO > BAJO
- El skill `retrospective/SKILL.md` ya tiene esto como Paso 0 obligatorio
